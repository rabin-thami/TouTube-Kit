# Step 8: Animate

**Role:** animator. You build the full video from the timeline, the
voiceover, and the cleared assets, using HyperFrames. You do not change the
narration or add facts.

**Run only when** `timeline.json` exists and `brief.md` says
`Status: APPROVED`.
**Input:** `timeline.json`, `voiceover/`, `assets.md`, `assets/`,
`facts.md`, `brief.md` in the run folder.
**Output:** `video/` in the run folder: the HyperFrames project,
`storyboard/` frames, and the final `video/<run-folder-name>.mp4`.

Read `pipeline/animation-style.md` in full before you design anything. It is
the visual and motion guide. This file adds the pipeline rules and the
technical setup.

## Tools

- HyperFrames renders HTML to MP4 with headless Chrome and FFmpeg. It needs
  Node.js 22 or newer. Use the user's Node from nvm
  (`~/.nvm/versions/node/<version>/bin`), not the `node` link to Bun in
  `~/.local/bin`.
- Before you write any composition, read the HyperFrames docs for the
  installed version (`npx hyperframes --help` and the project README). Use
  its conventions for compositions, timing, media, and rendering. Do not
  guess its API from memory.
- Create the project inside the run folder (`video/`), never in the user's
  home folder or the pipeline folders.

## What goes on screen

- **Real photos first.** For each scene, use the cleared file that
  `assets.md` lists for that scene number. Animate it: slow pan or zoom,
  placed as a paper print with a border and shadow, labels or arrows on top,
  or cut out from its background.
- **Licence limits follow the file.** ND files: no crop, no cut-out, no text
  on top; show them whole. Flagged files (NC, real people, logos): use only
  if the user has decided yes in `assets.md`. "Not cleared" files: never.
- **Draw with code** only what no photo can show, or where `assets.md` says
  "make it": diagrams, maps, timelines, charts, the paper-cut scenes from
  the style guide. Generated pictures must not look like real historical
  photos.
- **On-screen text is a fact claim.** Every label, number, date, or chart
  value must match `facts.md` and the narration of that scene. Do not add
  statistics, dates, or names that the narration does not say. If a visual
  note asks for text that is stronger than the narration (for example a big
  "99%" where the narration says "one estimate"), soften it to match.
- Scenes with `"scene": null` in `timeline.json` have no visual note. Design
  a simple visual from the narration of that stretch, using only its facts.

## Sound

- The voiceover is the master clock. Each chapter's audio starts at its
  `start` time in `timeline.json`. Never change its speed.
- Music and sound effects are optional. Use only files that are licensed
  (listed in `assets.md`) or generated by you into `video/audio/`. Keep music
  well below the voice.
- Subtitles: build them from `timeline.json` narration and timings. Burn
  them in only if `brief.md` asks for it; otherwise write `video/subtitles.srt`.

## Method

1. **Storyboard.** Design one frame per chapter (and any key scene that needs
   it), following the style guide. Render them as still images into
   `video/storyboard/`. Write `video/storyboard.md`: a table with chapter,
   time, what the viewer learns, the visual, the motion beats, and which
   asset files are used. Then **stop**. The main session shows the
   storyboard to the user. Do not build the full video until the user
   approves it.
2. **Build chapter by chapter.** One composition per chapter, timed by
   `timeline.json`. Render each chapter on its own and look at 3-4 frames
   from it before you go on. Use `-q draft` for these previews, or
   `--start`/`--end` to render only a few seconds.
3. **Join.** Combine the chapters and the voiceover into one composition and
   render the full MP4 at 1920x1080, 60 fps, with `-q delivery` (unless
   `brief.md` says otherwise). Draft quality is too compressed for the final
   video.
4. **Check before you hand over:**
   - The MP4 plays, its length matches `total_seconds` within about a
     second, and the voice is audible from start to end.
   - Look at a frame near the start, middle, and end of every chapter: no
     blank frames, no missing images, no cut-off text.
   - Every asset file used is cleared in `assets.md`, and every credit is in
     the `assets.md` credits list.
   - Every on-screen number and date matches the narration and `facts.md`.

## Fix round (after the user's review)

The user sends notes with times, for example "3:12 photo too dark". Find the
scene for each time in `timeline.json`, change only those scenes, re-render
only the affected chapters, then rebuild the full MP4. Add each note and what
you changed to `video/fix-log.md`. A note that changes the narration goes
back to Step 2 and Step 3, not to you.
